## Structure

1. **Container**: `<div class="uoa-tabs" data-uoa-tabs>`.
2. **List**: `<div class="uoa-tabs__list">` with an `aria-label` naming the set.
3. **Tabs**: `<button type="button" class="uoa-tabs__tab">` with a unique `id` and `aria-controls` to the panel.
4. **Panels**: `<section class="uoa-tabs__panel">` with a unique `id`, `aria-labelledby` to the tab and `tabindex="0"`.
   The first tab is active — markup order defines the default.

## Guidelines

### When to use

- For switching between equivalent views in the same spot: categories, languages, semesters.
- When users need one view at a time and the others stay available.

### When not to use

- For stacking independent sections read in sequence: use an accordion.
- For primary navigation between pages: use a navigation menu.
- For critical content that must be seen without clicking.
- For a single view: show it directly, without tabs.

### Variants

One variant: horizontal tabs with automatic activation (focus selects).
On narrow screens the list scrolls horizontally.

### Content

- Keep labels short, one or two words, parallel in form: "Programme · Enrolment · Grants".
- Make each panel self-contained, with its own heading when large.
- Keep `id`s unique per page — two groups never share an `id`.

### Behaviour

- Without JavaScript: buttons do nothing and all panels stay visible — nothing is lost.
- With JavaScript: automatic activation — arrows, Home/End and clicks select immediately.
- Only the active tab is in the Tab order (roving tabindex); inactive panels hide with `hidden`.

## Accessibility

- `tablist`/`tab`/`tabpanel` roles, `aria-selected` and roving tabindex are added by `tabs.js`
  (WAI-ARIA tabs pattern, automatic activation).
- Keyboard interaction:

  | Key | Action |
  | --- | --- |
  | `←` / `→` | Previous / next tab (flipped in RTL) |
  | `Home` / `End` | First / last tab |
  | `Tab` | Leave the list for the active panel |

- The list needs an `aria-label` (written in the markup, Greek or English).
- Panels have `tabindex="0"` so they stay keyboard-reachable when content overflows.
- In Windows High Contrast mode the list rule and the active indicator stay visible.
- Screen-reader testing (NVDA, VoiceOver) hasn't been done yet.

## API

### HTML / CSS

`.uoa-tabs` (+ `[data-uoa-tabs]`); children `.uoa-tabs__list` (`aria-label`), `.uoa-tabs__tab`
(`id` + `aria-controls`), `.uoa-tabs__panel` (`id` + `aria-labelledby` + `tabindex="0"`).

### JavaScript

`tabs.js` (entry: `@uoa/core/js`): `init(root)` wires every `[data-uoa-tabs]` not yet wired;
auto-runs on load. Also exports `select(group, tab, focus)` for adapters.

| Option / method / event | Type | Description |
| --- | --- | --- |
| `data-uoa-tabs` | attribute | The container that becomes a tab group |

### Platform adapters

#### WordPress (`packages/wordpress`, [ADR 0003](https://github.com/UniversityOfAthens/design-system-uoa/blob/develop/docs/adr/0003-wordpress-first-adapter.md))

The `uoa/tabs` block in the `uoa-blocks` plugin, with `uoa/tab` inner blocks (one panel each, any content). Tab names are typed straight into the list; in the editor every panel stays visible. The IDs and `aria-controls`/`aria-labelledby` pairs are generated unique per page; `tabs.js` loads only where the block is.

| Attribute | Type | Default | What it does |
| --- | --- | --- | --- |
| `label` | string | "Καρτέλες" | `uoa/tabs`: the tab list's accessible name |
| `title` | string | — | `uoa/tab`: the tab's name |

The block outputs the core reference HTML exactly, with no `wp-block-*` classes and no colour or spacing settings; `tests/phpunit/MarkupTest.php` checks it. It works on any theme: its styles come with the plugin.
